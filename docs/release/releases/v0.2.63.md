# Launcharr v0.2.63

## Summary

- Fixed local account management, which returned a server error when saving a profile or adding, re-roling, or deleting a local user ([#46](https://github.com/MickyGX/launcharr/issues/46)).
- Fixed a stale session surviving a wiped config, which could leave an old profile appearing to still exist and a deleted user keeping access ([#47](https://github.com/MickyGX/launcharr/issues/47)).
- Hardened startup against running with the example `SESSION_SECRET`.

## Fixed

- Fixed profile saves and local-user add/role/delete throwing `serializeLocalUsers is not defined`. The settings route was missing `serializeLocalUsers`, `setSessionUser`, `fetchPlexResources`, and `resolvePlexServerToken` from its handler context, so every handler that persisted users failed. Changing a local account password is now possible again. ([#46](https://github.com/MickyGX/launcharr/issues/46))
- Fixed the user profile password fields so a password shorter than 12 characters is rejected in the browser instead of silently submitting. ([#46](https://github.com/MickyGX/launcharr/issues/46))
- Fixed a `local` session referencing an account that no longer exists in config (for example after deleting the container and files, or removing a user) remaining authenticated with its cached username and role. The session is now dropped and the next request returns to login/setup. ([#47](https://github.com/MickyGX/launcharr/issues/47))

## Security

- A `local` session is now invalidated when its account is absent from config, so a deleted local user can no longer retain an active session or admin view.
- Launcharr now prints a prominent startup warning when `SESSION_SECRET` is left at the shipped placeholder value, since cookies signed with a publicly known key survive redeploys and can be forged. Generate your own with `openssl rand -hex 32`.

## Upgrade Notes

- No schema migration is required. Update and restart Launcharr.
- If you have not set `SESSION_SECRET` away from the example placeholder, do so now (`openssl rand -hex 32`) and restart. Existing sessions will be invalidated, which is expected.
