# Launcharr v0.2.62

## Summary

- Added qBittorrent API key authentication for qBittorrent 5.2 and newer ([#44](https://github.com/MickyGX/launcharr/issues/44)).
- The qBittorrent download queue and dashboard widget can now authenticate without a username/password login round-trip.
- Username/password login remains available for older qBittorrent versions.

## Added

- Added an optional **API Key** field to qBittorrent app settings. Generate a key in qBittorrent under Options -> WebUI -> API Key.
- When an API key is configured, Launcharr sends `Authorization: Bearer <key>` on qBittorrent WebAPI requests (`api/v2/torrents/info`, `api/v2/transfer/info`) and skips the cookie-based `api/v2/auth/login` flow.

## Changed

- qBittorrent no longer uses the username/password login when an API key is set. If the key is blank, Launcharr keeps the existing behaviour: it tries direct access first, then logs in with the configured credentials.
- A missing qBittorrent API key does not mark the app as unconfigured in Settings, because the key is optional.

## Upgrade Notes

- No schema migration is required. Update and restart Launcharr.
- API key authentication requires qBittorrent 5.2 or newer. On older versions, leave the API Key field blank and keep using username/password.
- Existing qBittorrent configurations work unchanged.
