# Launcharr v0.2.60

## Summary

- Fixed ARR calendar loading for deployments where Radarr or Sonarr are served behind a reverse-proxy path prefix.
- Hardened the browser-side ARR fallback path so it now mirrors the server-side URL join behavior.
- Added regression coverage for calendar fallback requests.

## Fixed

- Fixed ARR calendar direct fallback requests stripping configured app URL paths. A configured URL like `https://apps.example.test/sonarr` now falls back to `https://apps.example.test/sonarr/api/v3/calendar` instead of `https://apps.example.test/api/v3/calendar`.
- Fixed calendar modules showing `Unable to load Calendar calendar.` when the same-origin ARR proxy was unavailable but the browser fallback could otherwise reach the ARR instance.

## Changed

- Added a client-side regression test that simulates ARR proxy failure and verifies the calendar fallback preserves reverse-proxy subpaths.

## Upgrade Notes

- No schema migration is required. Update and restart Launcharr.
- If the calendar still fails after upgrading, hard refresh the browser so the updated `arr-overview.js` asset is loaded.
